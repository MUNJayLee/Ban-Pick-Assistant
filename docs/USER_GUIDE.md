> 更新：2026-10-29 · 适用于：React Web 控制台（:5173）+ FastAPI 识别服务（:8900）
> 相关：[架构说明](./ARCHITECTURE.md) · [文档索引](./INDEX.md)

## 0. 五分钟上手

```text
1. 双击 启动v3.0.bat            → 自动起 API(8900) + 前端(5173) + 打开浏览器
2. 手机开「开发者选项 → USB 调试」，数据线连电脑，手机上点「允许」
3. 页面左栏「设备」下拉选手机 → 点「开始识别」
4. 进游戏 BP         → 看板自动填 ban/pick，右侧推荐实时刷新
5. BP 完成           → 自动建草稿记录；打完一局结算自动回填胜负/MVP
6. 数据不准          → 「核对」Tab 人工标注，导出 CSV/JSON 给开发调算法
```

## 1. 环境与安装（首次）

### 环境要求

| 项 | 要求 |
|---|---|
| 系统 | Windows 10/11 |
| Python | 3.11+ |
| Node.js | 18+ |
| ADB | 默认 `D:\scrcpy\adb.exe`（没有则用 PATH 里的 `adb`） |
| 手机 | 安卓，开启「开发者选项 → USB 调试」 |
| 可选 | Supabase 项目（云端同步）、scrcpy（投屏） |

### 安装依赖

```powershell
# 前端依赖
npm install

# Python 依赖（国内镜像）
python -m pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

### 可选：云端同步配置

复制 `.env.example` 为 `.env`，填入 Supabase 的 `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY`（不配置也能用，仅本地保存）。

## 2. 启动

### 一键启动（推荐）

| 脚本 | 用途 |
|---|---|
| `启动v3.0.bat` | 日常使用：后台起 API + 前端，自动打开 http://localhost:5173/ |
| `调试启动.bat` | 测试用：保留 API 控制台窗口，能看到识别日志（阶段 / ban / 结算），排查问题用 |

关闭启动窗口不会停止服务；重启用任务管理器结束 `pythonw` / `node`，或重启电脑。

### 手动启动（开发）

```powershell
# 终端 1：API 识别服务
python scripts/api_server.py --port 8900

# 终端 2：前端
npm run dev
# 若 npm 脚本异常，可直接：
node node_modules\vite\bin\vite.js
```

| 地址 | 用途 |
|---|---|
| http://localhost:5173/ | Web 控制台 |
| http://127.0.0.1:8900/docs | API 文档（Swagger） |
| http://127.0.0.1:8900/api/health | 健康检查 |

### 检查服务是否正常

```powershell
Get-NetTCPConnection -LocalPort 8900,5173 -State Listen
Invoke-RestMethod http://127.0.0.1:8900/api/health
```

## 3. 连接手机

### USB 连接（推荐，延迟最低）

1. 手机：设置 → 关于手机 → 连续点「版本号」7 次 → 开启开发者选项。
2. 开发者选项 → 打开「USB 调试」。
3. 数据线连电脑，手机弹「允许 USB 调试」→ 点允许。
4. 命令行确认：

```powershell
D:\scrcpy\adb.exe devices
# 正常输出：<序列号>   device
# 异常：unauthorized（没点允许）/ offline（换线换口）
```

5. 页面左栏「设备」下拉 → 选手机（📱 真机 / 🖥 模拟器）→ 点「开始识别」。

### WiFi 无线连接（可选）

前置：手机与电脑同一 WiFi；手机「开发者选项 → 无线调试」已开，或先用 USB 执行 `adb tcpip 5555` 后拔线。

页面左栏「设备配置」→ WiFi 连接：填手机 IP（如 `192.168.3.62`）+ 端口（默认 5555）→ 点「连接」。
连接成功后刷新设备列表，选择 `<IP>:5555` 设备。

### 投屏（可选）

双击 `启动投屏.bat`，按提示选 USB / WiFi，用 scrcpy 把手机画面镜像到电脑（不影响识别）。

## 5. BP 模拟页

### 左栏：设备与识别

| 区域 | 说明 |
|---|---|
| 设备 | 下拉选设备、刷新、手动识别（抓一帧立即识别）、开始/停止识别、设备配置 |
| 识别状态 | 阶段（待机/禁用/选将/最后调整）、我方阵营、玩家楼层、我的英雄、已识别 ban/pick、错误提示 |
| ADB 实时画面 | 手机画面预览（「手动识别」时刷新） |

### 右栏：BP 看板

- **双方 ban/pick 位**：自动填充；点任意位置可手动选英雄修正。
- **英雄池**：搜索（支持中文/拼音/首字母）后点选。
- **回合指示**：当前该谁选、我方还差哪些位置。
- **智能推荐**：按分路分组，缺位优先，带版本/克制/协同理由。
- **阵容分析**：BP 完成后展示双方阵容、克制关系与建议；可点「记录本次 BP」。

> 手动修改会被保留：前端增量同步，识别结果与你手填的不同时**不覆盖**手填值。

### 快捷键（BP 页）

| 快捷键 | 功能 |
|---|---|
| `Ctrl + Z` | 撤销上一步 |
| `Ctrl + Shift + R` | 重置当前 BP（有数据时弹确认框） |

> 输入框/搜索框内不触发快捷键。

## 6. 核对页（10-29 新增）

**用途**：人工核对自动识别的裁切是否居中、英雄名是否正确，产出标注数据用于改进算法。

数据来源：真机运行时自动抓的 `_diag/live_*.png` 帧（最多保留 150 张，按时间清理）。

### 操作流程

1. 顶部点「**核对**」Tab。
2. 左侧「**素材帧（N）**」列表：默认筛选 `ban`，可切 `ban / pick / selecting / other / 全部`（记住上次筛选）。
3. 点一帧 → 右侧显示 **10 个裁切卡片**（蓝 1~5、红 1~5），每张卡片包含：
   - 裁切头像（放大 4 倍）
   - 识别英雄名（低置信显示「?」；选人界面未选位显示紫色「分路图标」）
   - 高/低置信标记 + `gap` 分值
   - ✓ / ✗ 按钮 + 备注输入框
4. 用右上「**Ban 位 / Pick 位**」切换核对模式。
5. 逐张判断：
   - 裁切偏移 → 备注写「偏左 / 偏右 / 偏上 / 偏下」
   - 认错英雄 → 备注写「实际是孙膑」
   - 点 ✓（正确）/ ✗（错误）。**标记与备注自动保存**（右下显示「保存中...」）。
6. 查看进度：左下显示「已全标帧数 / 总帧数」进度条 + 标注总数；帧名前的 ✓ 表示该帧已核对过。

### 快捷操作

| 操作 | 方式 |
|---|---|
| 本帧全部正确 | 点「本帧全部正确」按钮或按 `1`（自动跳到下一帧） |
| 本帧全部错误 | 按 `0`（10 个位置全部标 ✗） |
| 上一帧 / 下一帧 | `←` / `→` |
| 关闭原图预览 | `Esc`（或点遮罩 / 「关闭」按钮） |
| 查看原图（大图预览） | 点帧名旁的「查看原图」 |

### 导出标注

| 按钮 | 内容 |
|---|---|
| **导出 CSV** | 带 BOM，Excel 直接打开中文不乱码；列：frame / kind / side / index / correct / note / at |
| **导出 JSON** | 完整标注结构（含时间），给程序处理 |

数据保存在 `_diag/review.json`；接口断开时会提示「保存失败」。

## 7. 记录页

- **自动建记录**：BP 完成 → 自动建一条草稿（同一局不会重复建）。
- **结算回填**：打完一局，结算界面被识别后，实际结果（赢/输）、MVP 自动回填。
- **我的英雄**：巅峰赛按玩家楼层自动识别；非 MVP 结算需手动确认。
- **查看详情**：点记录卡片右侧展开箭头，查看双方阵容 / ban / 实际结果 / 评分 / MVP / 奖牌 / 备注。
- **编辑**：记录右侧铅笔图标 → 可改双方 picks/bans、我的英雄、胜负、评分（0~16）、MVP/奖牌、备注，保存后自动同步（配置 Supabase 时）。
- **删除**：单条记录点垃圾桶图标立即删除（无二次确认，请谨慎）；「清空全部」有确认弹窗。
- **筛选**：顶部统计（总记录 / 预测正确 / 预测错误 / 正确率）+ 「我的英雄胜率」快捷筛选。
- **导出 Excel**：右上「导出 Excel」→ 生成 `BP记录_YYYY-MM-DD.xlsx`（Tauri 桌面端可选保存路径，浏览器直接下载）。
- **清空全部**：右上「清空全部」，需确认，不可恢复。

## 10. 常见问题

### Q1：设备列表是空的

```powershell
D:\scrcpy\adb.exe devices
```

- `unauthorized` → 手机上点「允许 USB 调试」
- `offline` → 换数据线 / 换 USB 口 / 重启 adb（`adb kill-server` 后重试）
- 完全没输出 → 手机没开 USB 调试，或驱动/线材问题
- WiFi 连接：确认手机和电脑同一网段，IP 正确

### Q2：阶段一直是「待机」

1. 先看「ADB 实时画面」有没有画面（没画面 = 设备问题，见 Q1）。
2. 有画面但阶段待机：可能不在 BP 界面（大厅/游戏内显示「待机」是正常的）。
3. 点「手动识别」强制识别一帧。
4. 仍是待机但画面确实是 BP → 把左栏画面截图 + `_diag/recog.log` 发给开发。

### Q3：ban/pick 识别不准

1. 手动点选修正（会被保留，不被覆盖）。
2. 用「核对」页把错误帧标 ✗ 并写备注，导出发给开发补样本。
3. 确认游戏界面没有被弹窗/聊天遮挡。

### Q4：我的英雄没有自动识别

- 仅巅峰赛支持按楼层识别；排位赛名字是白色，不适用。
- 非 MVP 结算没有玩家头像 → 手动在阵容分析里点选我方英雄。
- 结算识别有阈值，低置信时不写入 → 手动确认即可。

### Q5：服务起不来 / 页面打不开

```powershell
Get-NetTCPConnection -LocalPort 8900,5173 -State Listen
# 缺哪个就重启对应服务
python scripts/api_server.py --port 8900
npm run dev
```

### Q6：核对页提示「无法连接 API（8900）」

API 服务没起或已停止 → 重新启动 `python scripts/api_server.py --port 8900`，再点核对页左侧列表上方的刷新按钮。

### Q7：识别抖动会不会把已填的数据清掉？

不会。新一局检测有防抖：连续 3 次（约 6 秒）bans 为空才重置；手动填的内容不覆盖。

## 11. 已知限制

| 限制 | 说明 |
|---|---|
| 排位局楼层识别 | 仅巅峰赛金色昵称有效（3/4 左右） |
| 非 MVP 结算 | 无玩家头像，「我的英雄」需手动确认 |
| 选人界面 pick | 选人阶段的队伍头像是预选，**不识别**，等「最后调整」才填最终阵容 |
| 低置信英雄 | 显示「?」，需人工修正；绿发类（孙膑/庄周/蔡文姬）识别较弱 |
| 分路图标 vs 盾山 | 视觉相似，按阶段区分（pick 阶段过滤，final 不过滤） |
| API 地址 | 前端写死 `http://127.0.0.1:8900`，改端口需改代码 |
| 核对帧数量 | 诊断帧最多保留 150 张，过早的帧会被清理 |
